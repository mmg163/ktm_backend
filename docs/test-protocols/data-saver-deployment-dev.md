# Протокол: выкладка Data Saver на dev-стенд

Изменение OpenSpec `add-data-saver-core`, задачи 9.2, 5.2, 10.27. Дата: 2026-11-22. Протокол фиксирует фактически
проведённую выкладку и обнаруженные расхождения; чего не проверяли, так и указано.

## Цель и состав

- Выложить сервис Data Saver (контейнеры `migrate` и `data-saver`) на dev-стенд, накатить миграцию V001, подтвердить
  приём события из Kafka в журнал `ktm.events` (задачи 9.2, 5.2).
- Проверить штатную остановку и права файлов секретов на Linux.
- Замер производительности (10.27) и подтверждение допущений А1 и А4 (5.3) - не выполнялись, см. раздел «Не выполнено и открыто».

## Порядок выкладки (для повторения)

1. **Образ (разработчик).** Собрать локально: `docker build -t ktm-data-saver:local .` (linux/amd64); упаковать
   `docker save | gzip`; передать `scp` (148 МБ); сверить sha256 (`80b13dc8e5025e9dac0a1214e5825b8cc685c833c03d8c92801bb03c7754cbfb`
   совпал); на стенде `gunzip -c ... | docker load`.
2. **Каталог (разработчик).** Положить на стенд `docker-compose.yml` (серверный вариант, см. расхождения), `.env`,
   `.env.example`, `migrate/`, `db/`.
3. **Init БД (администратор БД).** Выполнить `db/init` суперпользователем (роли `ktm_migrator`, `ktm_app`, схема).
   `CREATE EXTENSION timescaledb` в скрипте закомментирован: расширение уже установлено (PR #8, смержен).
4. **Пароли ролей (администратор БД, обязательно до первого запуска).** Init создаёт роли без паролей. Задать
   `\password ktm_migrator` и `\password ktm_app`. Пока пароли не заданы, `migrate` падает с `password authentication failed`.
5. **Право на схему расширения (администратор БД).** `GRANT USAGE ON SCHEMA public TO ktm_migrator`. Без него V001
   падает на `create_hypertable(...) does not exist`, если USAGE на `public` отозван у PUBLIC (на стенде отозван).
   `CREATE` на `public` не выдаётся.
6. **Сеть (разработчик + администратор).** Подсеть проекта закреплена в compose: `172.28.10.0/24`. Администратор
   открывает на файрволе хоста порты 5432 и 9092 для этой подсети и добавляет в `pg_hba.conf`:
   `hostssl ktm_revisor ktm_app,ktm_migrator 172.28.10.0/24 scram-sha-256`; перечитывает конфигурацию PostgreSQL.
7. **Секреты (администратор / владелец стенда).** Создать `secrets/ktm_app_password` и `secrets/ktm_migrator_password`,
   владелец `1654:1654`, права `0400`. Содержимое в протокол и в `.env` не попадает.
8. **Запуск.** `docker compose up -d`. Ожидание: `migrate` Exited (0), `data-saver` Up (healthy).
9. **Проверка здоровья.** С хоста: `curl 127.0.0.1:8090/health/ready` -> 200.
10. **Сквозная проверка.** Отправить тестовое сообщение в топик, проверить lag группы `ktm-data-saver` и строку в
    `ktm.events`. Тестовую строку удалить нельзя (журнал неизменяем, `ktm_app` имеет только SELECT/INSERT), поэтому
    выполнять один раз и помечать `payload.test=true`.
11. **Остановка.** `docker compose stop data-saver`, проверить код выхода и лаг; запустить сервис снова.

## Выявленные проблемы и решения

| # | Проблема | Причина | Решение |
|---|---|---|---|
| 1 | Первый запуск: `migrate` - `timeout expired` на 10.14.0.6:5432 | Файрвол хоста пропускал только подсеть сети skud 172.18.0.0/16; автоподсеть проекта 172.19.0.0/16 и стандартный bridge 172.17.0.0/16 блокировались (и PostgreSQL 5432, и Kafka 9092; диагностика `pg_isready`/`nc` из временных контейнеров) | Подсеть проекта закреплена `172.28.10.0/24`; администратор открыл 5432 и 9092 для неё и добавил строку `hostssl` в `pg_hba.conf`. Принцип: правила файрвола и `pg_hba` привязаны к подсети, а автоподсеть Docker зависит от порядка создания сетей, поэтому подсеть закреплена |
| 2 | `migrate`: `password authentication failed` | Init создаёт роли без паролей | Администратор задал пароли (шаг 4); шаг включён в порядок выкладки как обязательный |
| 3 | V001 упала: `create_hypertable(...) does not exist` | У `ktm_migrator` нет USAGE на схему `public` (на стенде отозван у PUBLIC, hardening; `has_schema_privilege` = false) | На стенде выдано вручную `GRANT USAGE ON SCHEMA public TO ktm_migrator`. Смысл решения: USAGE на схему расширения минимально необходим, CREATE на `public` не выдаётся. Фикс init смержен в `main` (PR #10, коммит d55f2c7); на стенде USAGE был выдан вручную до слияния |

## Расхождения

1. **Compose стенд / репозиторий.** Серверный `docker-compose.yml` отличается от `deploy/data-saver/docker-compose.yml`:
   убрана секция `build`; `../../db` заменено на `./db`; добавлено `ports: 127.0.0.1:${DataSaver__Health__Port}:...`;
   добавлено `networks.default.ipam.subnet: 172.28.10.0/24`. Эти правки **в репозиторий пока не перенесены**; до
   переноса стенд нельзя воспроизвести из репозитория без ручных правок.
2. **Топики и контракт.** `docs/api/kafka-event-format.md` п. 1 и ADR-0002 (единый входящий топик `ktm.events.raw`,
   9 партиций, хранение 7 суток) расходятся со стендом: единого `ktm.events.raw` нет, топики по источникам
   (`ktm.events.raw.skud`, `.cv`, `.1c-do`), у `skud` и `rejected` по 3 партиции. Решение лида: сейчас читается только
   `ktm.events.raw.skud`; планируется подписка на все источники регулярным выражением `^ktm\.events\.raw\..+` (подходят
   `raw.skud`, `.cv`, `.1c-do`; не подходят `rejected` и `dlq`). Открытая проверка: режим regex проектом тестами не
   проверялся; librdkafka понимает префикс `^` в `Subscribe`, но на стенде это не проверено. Контракт и ADR не
   изменялись; их приведение к решению - отдельная задача. Пример выражения добавлен комментарием в
   `deploy/data-saver/.env.example`.
3. **Версия TimescaleDB.** На стенде 2.31.0, в репозитории проверялось на 2.32.1; миграция V001 на 2.31.0 отработала.
   Версия на предприятии неизвестна.
4. **Init.** Расхождения нет: стенд и репозиторий согласованы (фикс USAGE на `public` в `main`, PR #10); на стенде грант выдавали руками. Строка `CREATE EXTENSION timescaledb`
   закомментирована (PR #8, смержен).

## Не выполнено и открыто

- **Замер производительности на стенде (10.27) и подтверждение допущений А1 и А4 (5.3)** - не выполнялись по решению
  лида («не будем»). Риски: нет измеренных данных по НФТ (500 событий/с в пике, 5 минут до отражения события) на стенде
  предприятия; допущения А1 и А4 остаются непроверенными.
- Остановка под нагрузкой с недописанной пачкой - не проверялась.
- Подписка регулярным выражением - не проверялась (расхождение 2).
- Docker в CI - неизвестно.
- Версия TimescaleDB на предприятии - неизвестна.
- Перенос правок compose в репозиторий - не сделан.
- Тестовая строка `test-datasaver-deploy-20261122-1` осталась в журнале; удалить может только администратор БД.
