# Приложение Б. Этапы разработки, приёмка и критерии готовности

Приёмка выполняется по сценариям, отражающим реальные кейсы предприятия. Для
каждого сценария должны быть указаны входные данные, ожидаемый результат,
допустимая задержка обработки, статус кейса и правило отображения на дашборде.
Сценарии разрабатываются в рамках ЧТЗ каждого этапа.

## Б.1. Этапы разработки и внедрения

Разработка и внедрение разбиты на 6 этапов, длительность каждого этапа — 8
рабочих недель, общая продолжительность — 48 рабочих недель. Рабочая неделя
составляет 5 рабочих дней (понедельник — пятница, без учёта нерабочих
праздничных дней).

Уже после 3-го этапа должна появиться работающая система в версии MVP.

### Этап 1. Аудит и обследование

**Состав работ**

- обследование источников данных: СКУД, система видеонаблюдения, 1С:ДО, 1С:ERP и
  иные источники;
- фиксация особенностей источников данных, достоверности и правдивости данных;
- сбор информации о номинальных и реальных должностных обязанностях сотрудников
  и руководителей для формирования алгоритмов движка правил;
- выявление проблемных точек и составление рекомендаций;
- анализ и проверка исходных данных в информационных системах предприятия,
  определение их достаточности, полноты, корректности и технической пригодности
  для выполнения последующих этапов;
- фиксация в ЧТЗ перечня источников данных, используемых показателей и
  параметров, подтверждённых как достаточные и пригодные для последующих этапов;
- при выявлении отсутствующих, неполных, недостоверных либо технически
  непригодных данных — документированное описание недостатков с указанием
  конкретных информационных систем и рекомендациями по их устранению;
- разработка ЧТЗ для следующего этапа.

**Результат этапа**

Отчёт об обследовании предприятия:

- реестр источников данных;
- описание существующих бизнес-процессов (по ролям), согласно которым обязаны
  работать сотрудники;
- перечень выявленных ограничений и рисков внедрения;
- рекомендации по подготовке инфраструктуры и данных.

Техническое описание реализации системы:

- общая архитектура системы — единое визуально-текстовое описание того, как будет
  устроена система;
- паспорта источников данных — систематизированное описание всех внешних систем,
  с которыми предстоит интегрироваться;
- модель данных (ER, «сущность — связь»);
- описание API интеграции.

**Передаваемые материалы**

- ЧТЗ для Этапа 2;
- перечень товарно-материальных ценностей (ТМЦ) и оборудования, необходимых для
  выполнения работ на последующих этапах, с указанием сроков потребности в каждой
  позиции (сроки могут уточняться в ЧТЗ на этапы работ).

**Критерии приёмки этапа**

- обследованы все согласованные источники данных;
- сформирован перечень интеграций;
- подготовлено и согласовано ЧТЗ для Этапа 2;
- документы переданы.

### Этап 2. Разработка ядра Системы

**Состав работ**

- разработка back-end и пилотной версии пользовательского интерфейса (front-end,
  UI);
- интеграция с двумя первыми источниками — СКУД и системой видеонаблюдения;
- пилотная интеграция и тестирование приёма данных из 1С:Документооборот (задачи
  сотрудников);
- формирование цифровых профилей на пилотную группу сотрудников, подлежащих
  профилированию;
- сбор информации в единую БД;
- разработка ЧТЗ для следующего этапа.

**Выполненные работы**

- развёрнута базовая версия Системы;
- реализована авторизация пользователей;
- реализован функционал создания/заполнения цифровых профилей сотрудников;
- реализованы интеграции со СКУД и системой видеонаблюдения;
- реализована пробная интеграция с 1С:Документооборот;
- реализована единая база хранения событий;
- подготовлено и согласовано ЧТЗ для Этапа 3.

**Передаваемые материалы**

- отчёт;
- исходный код разработанных модулей;
- инструкция по развёртыванию;
- описание архитектуры;
- протокол функционального тестирования;
- ЧТЗ для Этапа 3.

**Критерии приёмки этапа**

- Система развёрнута на тестовом контуре;
- присутствует возможность создать и заполнить профиль сотрудника;
- данные из СКУД поступают в профиль сотрудника;
- данные видеоаналитики поступают в профиль сотрудника;
- подготовлено и согласовано ЧТЗ для следующего этапа.

### Этап 3. Профили и базовая бизнес-логика оценивания производительности

**Состав работ**

- интеграция с остальными источниками информации (1С:ERP, закупки и т.д.);
- настройка ролей и правил интерпретации данных, создание движка правил;
- настройка оценивания каждого сотрудника (балл 0–100);
- создание пилотных версий отчётов по сотрудникам в базовой версии;
- проверка Системы и тестирование на ошибки;
- разработка ЧТЗ для следующего этапа.

**Выполненные работы**

- реализован движок правил;
- реализован расчёт показателей сотрудников;
- реализован расчёт интегрального балла;
- реализованы сигналы и инциденты;
- реализованы базовые дашборды;
- реализованы основные интеграции;
- Система введена в тестовую эксплуатацию в статусе MVP;
- подготовлено и согласовано ЧТЗ для Этапа 4.

**Передаваемые материалы**

- отчёт;
- исходный код разработанных модулей;
- протокол испытаний;
- отчёт о результатах тестовой эксплуатации;
- ЧТЗ для Этапа 4.

**Критерии приёмки этапа**

- доступен цифровой профиль сотрудника;
- доступен вычисляемый и обновляемый рейтинг сотрудников;
- доступны вычисляемые и обновляемые рейтинги подразделений;
- формируются инциденты при фиксации нарушений;
- отображаются причины отклонений;
- доступны базовые дашборды;
- обеспечивается сохранение истории событий;
- выполнены согласованные сценарии приёмочных испытаний.

### Этап 4. Доработка Системы по обратной связи тестовой эксплуатации

**Состав работ**

- исправление ошибок и недочётов;
- отработка пожеланий, возникающих в процессе эксплуатации Системы;
- расширение количества сотрудников, профилируемых Системой;
- доработка дашбордов под конкретные запросы топ-менеджмента;
- тонкая настройка правил и движка правил;
- улучшение скорости работы и UX;
- разработка ЧТЗ для следующего этапа.

**Выполненные работы**

- устранены замечания тестовой эксплуатации;
- реализованы согласованные доработки;
- расширен охват профилируемых сотрудников;
- оптимизирована производительность;
- подготовлено и согласовано ЧТЗ для Этапа 5.

**Передаваемые материалы**

- отчёт;
- исходный код разработанных модулей;
- ЧТЗ для Этапа 5.

**Критерии приёмки этапа**

- устранены все согласованные замечания;
- реализованы согласованные доработки;
- подтверждена работоспособность системы после изменений;
- отсутствуют критические ошибки.

### Этап 5. Масштабирование и переход к опытной эксплуатации

**Состав работ**

- масштабирование Системы на всех сотрудников, подлежащих профилированию;
- обучение руководителей работе с дашбордами и Системой;
- перевод Системы из тестового режима в продуктивный;
- сбор обратной связи и исправление ошибок;
- разработка ЧТЗ для следующего этапа.

**Выполненные работы**

- Система внедрена для всех согласованных сотрудников;
- проведено обучение пользователей;
- проведена опытно-промышленная эксплуатация;
- подготовлено и согласовано ЧТЗ для Этапа 6.

**Передаваемые материалы**

- отчёт;
- исходный код разработанных модулей;
- материалы для обучения работе с системой;
- акт внедрения системы в опытную эксплуатацию;
- ЧТЗ для Этапа 6.

**Критерии приёмки этапа**

- проведено обучение пользователей;
- подписан акт опытно-промышленной эксплуатации;
- критические замечания отсутствуют.

### Этап 6. Внедрение технологий искусственного интеллекта

**Состав работ**

- надстройка ИИ-слоя поверх уже работающей системы;
- обучение ИИ на истории;
- разработка функционала предсказания проблем;
- разработка функционала нахождения скрытых паттернов с помощью ИИ, которые
  человек может упустить;
- финальная настройка правил с учётом рекомендаций ИИ.

**Выполненные работы**

- в систему внедрён ИИ-модуль;
- реализовано прогнозирование рисков;
- реализовано выявление аномалий и нетипичных событий;
- реализовано формирование рекомендаций по выявленным рискам и аномалиям;
- реализован пользовательский интерфейс для просмотра прогнозов, аномалий,
  влияющих факторов и рекомендаций ИИ;
- выполнено обучение ИИ-модуля на исторических данных предприятия;
- подготовлен комплект документации на ИИ-модуль.

**Передаваемые материалы**

- исполняемые программные компоненты и конфигурационные файлы ИИ-модуля;
- описание архитектуры ИИ-модуля и используемых алгоритмов формирования
  рекомендаций;
- материалы для обучения работе с ИИ-модулем;
- отчёт о результатах обучения и тестирования ИИ-модуля на исторических данных.

**Критерии приёмки этапа**

- ИИ-модуль интегрирован в действующую Систему и функционирует без нарушения её
  основной работоспособности;
- пользователям доступны интерфейсы просмотра прогнозов, аномалий и
  рекомендаций;
- ИИ-модуль способен выполнять анализ исторических данных предприятия и
  формировать рекомендации на их основе;
- по запросу пользователя Система отображает факторы, повлиявшие на формирование
  рекомендации либо прогноза;
- обеспечена возможность включения и отключения ИИ-функций без остановки работы
  Системы;
- при отключении ИИ-модуля основная функциональность Системы сохраняется в
  полном объёме;
- выполнены и успешно пройдены приёмочные испытания по согласованным сценариям;
- передан полный комплект документации и исходных кодов.

## Б.2. Критерии готовности

| Блок | Критерий готовности |
|---|---|
| Интеграции | Данные поступают из согласованных источников, фиксируется доступность источников и уровень доверия |
| Кейсы | События формируются в кейсы, имеют статус, ответственного, источник подтверждения и историю действий |
| Производственный контекст | Технические сбои и производственные причины отделяются от действий сотрудника |
| Дашборды | Показатели, причины, доверие к данным и рекомендуемые действия отображаются для выбранной роли |
| Закупочный пилот | Заявки анализируются по обоснованности, остаткам, цене, поставщикам, срокам и документам |
| Аудит | Все изменения статусов, правил, комментариев и решений фиксируются в журнале |
| Безопасность | Доступ ограничен ролями; запрещённые операции невозможны без соответствующих прав |
| Нагрузка | Система проходит согласованные нагрузочные испытания без потери критичных событий сверх допустимого порога |

## Б.3. Документация, передаваемая по завершении работ

- руководство пользователя по ролям;
- руководство администратора;
- описание интеграций и форматов обмена;
- регламент резервного копирования и восстановления;
- протоколы функционального и нагрузочного тестирования;
- описание методики расчёта показателей и правил доверия к источникам.
