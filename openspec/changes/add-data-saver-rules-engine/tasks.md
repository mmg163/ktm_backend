# Tasks

Код пишет роль `developer`; после каждой группы - `reviewer`. Чекбокс отмечается, когда поведение реализовано целиком и
проверка из задачи проходит. Запуск тестов - `$run-tests`. Тесты - только на поведение кода и БД (не на csproj, compose, `.env`,
документы). Решения и формулировки - `docs/adr/0005-data-saver-rules-engine.md` (редакция 3); ссылки «ADR п. X» - на него.

Объём первой итерации (решения лида 2026-11-23): правила - **таблица БД в урезанном варианте** (одна миграция схемы + отдельная
миграция с примерами, `ktm_app` только `SELECT`, опрос раз в минуту, без триггеров, аудита, `LISTEN/NOTIFY`); условие - нотация
JsonLogic (`and`, `or`, `!`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `var` с точечным путём, диапазон - трёхаргументный `<=` с включительными
границами) при собственном строгом вычислителе и валидаторе, библиотека не подключается. Отложены и в задачи не входят: `in`,
`missing`-подобное «пусто/заполнено», сравнение `==`/`in` без учёта регистра; **регулярное выражение (`regex`) - дополнение после закрытия
групп 1-8, решение лида 2026-11-23: группа 9, ADR п. 0.1 и 2.7 (группы 1-8 и их чекбоксы не пересматриваются)**; перечитывание «по команде» (только опрос;
отступление от постановки, ADR п. 2.10); триггер версии, аудит, `NOTIFY` (ADR, приложение A). Изменений `docker-compose.yml`,
`.env.example`, `Dockerfile` не требуется. Архитектура отложенного не исключает (реестр операторов, `IRuleSource`,
`IRuleChangeSignal`) - задачи 2.1 и 3.4.

## 2. Ядро: язык условий (`Ktm.DataSaver.Core/Rules`, unit-тесты `Ktm.DataSaver.Tests`)

- [x] 2.1 Модель и реестр операторов: `RuleDefinition`, интерфейс оператора (ключ, разбор операндов и проверка при загрузке, вычисление, имя для трассировки) и реестр; регистрируются только `==`, `!=`, `<`, `<=` (две формы: два операнда и три - диапазон), `>`, `>=`; прочий ключ (`in`, `missing`, `regex`, `if`, `+` ...) - ошибка «оператор не поддерживается»; unit-тест: тестовый оператор, зарегистрированный в тесте, работает без правок узлов `and`/`or`/`!` и стадии (доказательство расширяемости)
- [x] 2.2 `FieldPath`: разбор грамматики `var` (ADR п. 2.5: сегменты через точку, `[A-Za-z0-9_-]+`; цифровой сегмент у массива - индекс), вычисление по `JsonElement` -> «значение / отсутствует»; проверка первого сегмента по списку полей конверта v1; unit-тесты: `externalPersonId`, `payload.confidence`, `payload.items.1.code`, несуществующий путь, путь через не-объект, индекс за границей, цифровой ключ объекта, ошибочные пути (`""`, `a..b`, `a.`, `a[0]`, `*`, `unknownField`) отвергаются, регистр значим
- [x] 2.3 Узлы и вычислитель: `{"and": [...]}`/`{"or": [...]}` (логические, короткое замыкание, непустой массив), `{"!": узел}` и `{"!": [узел]}` (оператор `!` оставлен решением лида), трассировка сработавших листьев для сработавшего правила; узел - объект ровно с одним ключом (два ключа, пустой объект - ошибка); unit-тесты **на каждый узел**: `and` (все истинны / одна ложна / пустой массив отвергается), `or` (один истинен / все ложны), `!` (инверсия, обе формы записи, отсутствующее поле: `!(x >= 0.5)` истинно, `x < 0.5` ложно), вложенность 3 уровня, глубина 9 и 65 узлов отвергаются; побитовая семантика исключена (результат всегда булев)
- [x] 2.4 Операторы `==`/`!=`: строка (ordinal, регистр значим), число как `decimal` (`1` = `1.0`), булево, `null` (только явный JSON `null`; отсутствие - ложь), отсутствует/другой тип (`"5"` не равно `5`) -> ложь, число вне `decimal`; `!=` = отрицание `==` (отсутствующее поле «не равно», зафиксировано в документации) и пара `!=`/`!(==)` совпадает; форма операндов: `[var, литерал]` и `[литерал, var]` равнозначны, два литерала / два `var` / три операнда / `var` с массивом (значение по умолчанию) -> ошибка правила; unit-тесты на каждый случай
- [x] 2.5 Операторы `<`, `<=`, `>`, `>=` (два операнда): числа (`decimal`, граница включительно/нет), даты-строки (RFC 3339 с `Z` и со смещением, сравнение по моменту времени, дата без зоны/не дата в значении правила -> ошибка загрузки, поле-нестрока или неразбираемая дата -> ложь), литерал слева читается зеркально (`{"<": [5, var]}` = `var > 5`), смешение типов -> ложь, строка-число (`"0.3"`) к числу не приводится, отсутствует/`null` -> ложь, число вне `decimal` -> ложь; unit-тесты на каждый случай (в том числе `occurredAt` и `payload.dueAt`)
- [x] 2.6 Диапазон `{"<=": [нижняя, {"var": ...}, верхняя]}` (**обе границы включительно**, решение лида): unit-тесты: значение **равно нижней границе** (истина), **равно верхней** (истина), внутри (истина), чуть ниже нижней и чуть выше верхней (ложь), числа и даты (в т.ч. смещение зоны на границе), отсутствует/`null`/строка вместо числа -> ложь, вырожденный диапазон `[5, var, 5]` (истина для 5); загрузка: нижняя > верхней, `var` не посередине, число и дата вперемешку, дата без зоны, не литерал, трёхаргументные `<`, `>`, `>=` -> ошибка правила; эквивалентность диапазона и `and(>= нижняя, <= верхняя)` на наборе значений
- [x] 2.7 `ConditionCompiler` (JSON-условие -> узлы; ничего не бросает, возвращает список ошибок): каждая ошибка правила отдельным тестом с текстом `<путь в дереве>: <причина>` (не объект, два оператора в узле, неподдерживаемый оператор (`in`, `missing`, `regex`, `if`), неверная форма операндов, неизвестное верхнеуровневое поле пути, ошибочный путь, глубина 9, 65 узлов, неизвестный `source`); корректное условие по одному на оператор компилируется; значения из сообщений в текстах ошибок отсутствуют (их там нет)
- [x] 2.8 Сверка схемы условия и компилятора: набор образцов (допустимые и недопустимые условия; образцы - из проверки схемы teamlead: два литерала, два `var`, `var` с массивом, `in`, пустой `and`, трёхаргументный `<`, пустой путь, `all`/`any` вместо `and`/`or`) проверяется и `rejection-condition.schema.json` (через `ISchemaValidator`), и компилятором; расхождения допустимы только по семантике, которую схема выразить не может (даты без зоны, порядок границ, глубина), и перечислены в тесте явным списком
- [x] 2.9 Примеры `V003` (парсятся из файла миграции) проходят `ConditionCompiler` без ошибок при принудительной компиляции (включая выключенные) и проходят схему условия (тест на поведение компилятора на данных поставки, не на формат файла как конфига)
